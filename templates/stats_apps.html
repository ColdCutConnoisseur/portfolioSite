About

This began as a simple script that would fetch live stats for NCAA basketball games during this year's March Madness tournament and try to pace out the final points to be scored by each time. At first, the script just used simple moving averages, but by the end of the tournament this had turned into a full fledged machine learning model and workflow.

The end product was a regression model that was based off observations from all games played within the 2024-25 Season.

Backtester App

The backtester application is essentially a fork of the trader app, using a similar strucuture and setup. It differs however, in that it allows for testing the configured trade strategy over historical data, and it also exposes additional functionality that allows for a stepthrough of the historical data and trades. API and Dashboard

Here's a barebones API + dashboard (only purpose is really just a quick visual confirmation that everything is working) I created with python's flask framework and host for free on pythonanywhere.com. I set the TradingView webhooks to the API call of that website that adds trade signals to a database within this flask app. I set the payload from TradingView's side to include attributes like trade direction, quantity, price, and an API key used for authentication purposes (so that trades can't be spoofed by others). Whenever new signals are posted and unprocessed, they are displayed on this dashboard page simply as a timestamp of when they occurred.

Desktop App

This app handles all authentication on the broker side, as well as functionality that continues to refresh authentication as tokens near expiration. This ensures that the session does not go stale or that the user is not logged out during a trade session. The app then subscribes to market streams for any equities set to trade in the app's configuration. I use a python requests stream / session object to handle market update messages and keep a current orderbook for anything I am trading. A separate thread is started and a timeout occurs every (configured) few seconds. On a timeout, the application will poll the flask app to see if any new trade signals have arrived since the last poll. If a new signal has occurred, the app translates, formats, and sends a new order to my broker's API. An audit trail is provided both in the 'Processed Signals' and the 'Trade Review' windows. My trading exposure is then updated in the 'Open Positions' window.

Broker API Execution

Here an open trade is reflected on the broker's side. It remains open until an exit call is received by my trading application. Again this is forwarded by the underlying TradingView strategy and passed on to my API / database by webhook.
