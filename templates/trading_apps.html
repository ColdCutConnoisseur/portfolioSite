Automated Trading & Strategy Development

Here's some of the strategy development work I've done & an example of an automated trading setup I employ myself.

About

This project bundled:

  • an API connection to Interactive Brokers for sending and querying orders as well as fetching market data.
  • a trade strategy class, allowing for writing and easily configuring custom trade strategies.
  • charting functionality for displaying both historical and live data as well as trade indicator overlays.
  • functionality for trading in simulation versus live trading.
  • and a graphical user interface to tie everything together, complete with a separate configuration page.


As an add on, the same underlying app skeleton was also later used to create a backtester application. The trade backtester allowed a user to run a specified trade strategy over historical data to see how the strategy would have performed during that time period. Backtesters are typically employed in order to decide whether or not to run a new trading strategy.

The backtester app has functionality for plotting the historical data over the specified time period and configured data resolution, and also includes peripheral functionality like plotting trade take-profits and stops on the chart, plotting trade indicator objects, and has helper functions that allow for the user to step through market data updates or skip to notable events like trade setups, order sends, order fills, order cancels, trade exits, etc. It also has a summary printout providing statistics like percentage of winning / losing trades, etc, etc.

Backtester App

The backtester application is essentially a fork of the trader app, using a similar strucuture and setup. It differs however, in that it allows for testing the configured trade strategy over historical data, and it also exposes additional functionality that allows for a stepthrough of the historical data and trades. It also displays the computed trade indicators and profit / loss levels for quick visual highlighting of past trades.

API and Dashboard

Here's a barebones API + dashboard (only purpose is really just a quick visual confirmation that everything is working) I created with python's flask framework and host for free on pythonanywhere.com. I set the TradingView webhooks to the API call of that website that adds trade signals to a database within this flask app. I set the payload from TradingView's side to include attributes like trade direction, quantity, price, and an API key used for authentication purposes (so that trades can't be spoofed by others). Whenever new signals are posted and unprocessed, they are displayed on this dashboard page simply as a timestamp of when they occurred.

Desktop App

This app handles all authentication on the broker side, as well as functionality that continues to refresh authentication as tokens near expiration. This ensures that the session does not go stale or that the user is not logged out during a trade session. The app then subscribes to market streams for any equities set to trade in the app's configuration. I use a python requests stream / session object to handle market update messages and keep a current orderbook for anything I am trading. A separate thread is started and a timeout occurs every (configured) few seconds. On a timeout, the application will poll the flask app to see if any new trade signals have arrived since the last poll. If a new signal has occurred, the app translates, formats, and sends a new order to my broker's API. An audit trail is provided both in the 'Processed Signals' and the 'Trade Review' windows. My trading exposure is then updated in the 'Open Positions' window.

Broker API Execution

Here an open trade is reflected on the broker's side. It remains open until an exit call is received by my trading application. Again this is forwarded by the underlying TradingView strategy and passed on to my API / database by webhook.

I was also impressed with the performance of this application being that it is written in python; the app allows for better execution in terms of time & price than I had originally imagined it would.
